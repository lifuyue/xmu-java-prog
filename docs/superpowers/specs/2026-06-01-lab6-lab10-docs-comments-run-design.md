# LAB6-LAB10 注释、快速启动与 README 改进设计规格

日期：2026-06-01

## 1. 背景与目标

本规格用于改进 `LAB6` 到 `LAB10` 的可读性和运行说明。目标是在不改变程序功能和实验结果的前提下，让初学者可以更快理解每个实验做了什么、怎么运行、主要类如何分工，以及关键代码为什么这样写。

本次交付范围：

- 为 `LAB6` 补充 README。
- 统一完善 `LAB7`、`LAB8`、`LAB9`、`LAB10` 的 README。
- 更新仓库根目录 README，使总览覆盖 `LAB1` 到 `LAB10`。
- 为 `LAB6` 到 `LAB8` 的非 Maven 实验补轻量快速启动脚本。
- 为 `LAB6` 到 `LAB10` 的 Java 源码补关键逻辑注释。
- 保持已有程序行为、数据文件格式、截图和报告文件不变。

## 2. 已确认决策

- 注释范围采用“关键逻辑注释”：解释类职责、入口流程、核心算法、事件处理、文件读写、MVC/JavaFX 结构，不给简单 getter、setter 和明显赋值逐行加注释。
- README 和脚本说明面向 Java 初学者，要求可复制运行、前提清楚、语言直接。
- 不把课程实验重构成新架构，不引入新的构建系统。
- `LAB9`、`LAB10` 保持 Maven JavaFX 运行方式。
- `LAB6`、`LAB7`、`LAB8` 使用 `javac` 直接编译运行，并补充脚本降低命令记忆成本。

## 3. 当前项目状态

`LAB6` 到 `LAB10` 当前结构如下：

- `LAB6`：5 个控制台实验小题，没有 README。
- `LAB7`：7 个泛型与集合控制台小题，已有 README 和运行日志。
- `LAB8`：Swing GUI 实验，已有 README、截图和实验报告生成脚本。
- `LAB9`：Maven JavaFX 实验，已有 README、截图脚本和报告生成脚本。
- `LAB10`：Maven JavaFX 文件处理实验，已有 README、数据文件、截图和报告生成脚本。

现有不足：

- 根 README 只介绍到 `LAB3`，与当前仓库内容不一致。
- 各实验 README 的结构和详细程度不统一。
- 非 Maven 实验的运行命令需要手工拼接，初学者容易输错路径或类名。
- Java 源码整体缺少解释关键设计的注释。

## 4. 备选方案与选择理由

### 4.1 方案 A：统一文档 + 轻量脚本 + 关键注释

为每个实验补统一 README 结构，给 `LAB6` 到 `LAB8` 增加简单 `run.sh`，并在源码关键位置补注释。

优点：

- 覆盖用户要求的 README、快速启动和代码注释。
- 改动集中在说明性材料和小脚本上，不影响程序行为。
- 初学者可以先运行，再按 README 和注释理解设计。

缺点：

- 需要逐个实验检查入口类和输入方式，避免脚本说明与实际代码不一致。

结论：采用此方案。

### 4.2 方案 B：只补 README 和命令

只完善 README，不修改源码注释。

优点：

- 改动最小。

缺点：

- 不能充分满足“给代码写注释”的要求。
- 初学者从 README 进入源码后仍然需要自己推断类职责。

结论：不采用。

### 4.3 方案 C：完整脚手架化运行入口

为每个 LAB 建立完整命令体系，例如统一构建、清理、截图、报告生成、运行菜单。

优点：

- 自动化体验最好。

缺点：

- 改动面超过当前目标，容易把课程实验变成脚手架工程。
- 对已有 Maven 和非 Maven 实验混合结构不够克制。

结论：不采用。

## 5. README 设计

每个 `LAB6` 到 `LAB10` 的 README 使用相近结构：

- `实验内容`：用简短语言说明本实验覆盖的题目和技术点。
- `目录结构`：列出每个小题或 Maven 工程主要文件。
- `快速启动`：给出从仓库根目录可直接复制的运行命令。
- `设计说明`：解释主要类如何分工、数据如何流动、为什么这样组织。
- `注意事项`：说明输入样例、GUI 运行前提、截图或报告生成命令。

根目录 README 改为仓库级总览：

- 说明仓库包含 `LAB1` 到 `LAB10` 和大作业目录。
- 用表格列出每个实验主题、目录和运行入口。
- 保留常用编译运行示例，但避免把所有实验的全部命令堆在根 README 中。
- 引导读者进入对应 `LABx/README.md` 查看细节。

README 的写法遵循初学者可读原则：

- 命令尽量从仓库根目录执行，例如 `bash LAB7/run.sh 4`。
- 每条命令前说明它运行的是哪一题。
- 对 Maven、JavaFX、Swing、控制台输入等前提用短句解释。
- 避免只写“运行程序”而不写入口类名和目录。

## 6. 快速启动脚本设计

`LAB6`、`LAB7`、`LAB8` 增加轻量 `run.sh`：

```text
LAB6/run.sh
LAB7/run.sh
LAB8/run.sh
```

脚本职责：

- 接收题号参数，例如 `bash LAB6/run.sh 5`。
- 根据题号选择对应源码目录和主类。
- 自动创建 `bin/` 目录并执行 `javac -d ... src/*.java`。
- 编译成功后执行对应 `java -cp ... MainClass`。
- 对需要示例输入的小题，在 README 中提供 `printf ... | bash LAB7/run.sh 5` 形式。

脚本不承担的职责：

- 不改写源代码。
- 不生成报告。
- 不删除已有截图、日志或数据文件。
- 不替代 `LAB9`、`LAB10` 的 Maven JavaFX 流程。

`LAB9` 和 `LAB10` 的快速启动保留为 README 命令：

```bash
mvn -f LAB9/pom.xml javafx:run
mvn -f LAB10/pom.xml javafx:run
```

截图和报告命令也写进对应 README，但作为可选命令，不混入最短启动路径。

## 8. 错误处理与边界

README 和脚本需要明确常见错误：

- 没有安装 JDK 或 `javac` 不在 PATH 中。
- JavaFX Maven 工程第一次运行需要下载依赖。
- GUI 程序需要桌面环境，不能只在纯终端无图形环境运行。
- 控制台题目如果等待输入，README 必须给出输入样例或说明如何手动输入。

脚本错误处理：

- 参数缺失时输出可用题号和示例命令。
- 未知题号时退出并提示支持的范围。
- 编译失败时让 `javac` 原样输出错误，脚本停止执行。

源码错误处理不做行为性重构，只在现有异常处理附近补充解释性注释。除非发现 README 命令无法运行，否则不改变业务逻辑。

对于 GUI 程序，验证以“能编译并打开主窗口”为准，不要求重新生成所有截图和 Word 报告。
